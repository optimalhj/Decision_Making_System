# 데이터 수집 매뉴얼: KBO 최신 시즌 데이터 받기

이 문서는 `kbo_sim/data_snapshot/`의 4개 CSV(`teams`, `batters`, `pitchers`, `matchup`)를
KBO 공식 기록실(koreabaseball.com)에서 오늘 날짜 기준으로 새로 받는 방법을 설명합니다.
설치·실행 방법은 [프로그램 매뉴얼](프로그램_매뉴얼.md), 데이터가 시뮬레이션에서 어떻게
쓰이는지는 [게임 규칙 매뉴얼 7절](게임_규칙_및_운영_매뉴얼.md#7-데이터와-시뮬레이션의-범위)을
참고하세요.

## 1. 빠르게 받기 (teams/batters/pitchers만, 수 분)

```shell
python tools/collect_kbo_data.py --no-matchup
```

`kbo_sim/data_snapshot/`에 `teams_20260908.csv`, `batters_20260908.csv`,
`pitchers_20260908.csv`처럼 **오늘 날짜가 붙은 파일**이 새로 생깁니다. 기존 파일(고정
파일명이든 다른 날짜의 파일이든)은 건드리지 않고 그대로 둡니다 — 지우고 싶으면 직접
지우세요.

## 2. 상대전적까지 전부 받기 (수 시간)

```shell
python tools/collect_kbo_data.py
```

옵션 없이 실행하면 `matchup_20260908.csv`(투수 vs 타자 상대전적)까지 받습니다. KBO
사이트에는 이 기록을 한 번에 여러 건 조회하는 방법이 없고 "투수 1명 + 타자 1명" 조합을
하나씩 조회하는 화면뿐이라, 팀이 다른 모든 투수x타자 조합(대략 7~8만 쌍)을 순서대로
조회해야 합니다. 그래서:

- 기본적으로 조회마다 약간씩 쉬어가고(`--delay`, 기본 0.25초) 동시 연결 수를 적게
  유지해(`--workers`, 기본 4) 사이트에 부담을 주거나 차단당하지 않도록 합니다.
- 진행 중 체크포인트(`data_snapshot/.matchup_checkpoint_YYYYMMDD.jsonl`)를 계속
  남기므로, 중간에 Ctrl+C로 멈추거나 네트워크가 끊겨도 처음부터 다시 할 필요가 없습니다.

```shell
# 중단된 수집을 이어서 진행 (같은 날짜로 다시 실행)
python tools/collect_kbo_data.py --resume
```

시간을 줄이고 싶으면 상대전적만 나중에 별도로 받을 수도 있습니다.

```shell
python tools/collect_kbo_data.py --no-matchup          # 1) 빠른 3종 먼저
python tools/collect_kbo_data.py --matchup-only         # 2) 상대전적은 나중에, 방금 받은 최신 파일 기준으로
```

## 3. 옵션

| 옵션 | 설명 |
|---|---|
| `--out-dir DIR` | 저장 위치 (기본 `kbo_sim/data_snapshot/`) |
| `--date YYYYMMDD` | 파일명에 쓸 날짜 (기본: 오늘). `--resume`으로 이어받을 때는 원래 실행한 날짜와 같게 지정해야 체크포인트를 찾습니다 |
| `--no-matchup` | 상대전적은 건너뛰고 teams/batters/pitchers만 |
| `--matchup-only` | teams/batters/pitchers는 새로 받지 않고, `--out-dir`의 최신 파일에서 선수 목록만 읽어 상대전적만 수집 |
| `--resume` | 중단된 상대전적 수집을 체크포인트에서 이어감 |
| `--delay 초` | 상대전적 조회 1건당 최소 대기시간 (기본 0.25) |
| `--workers N` | 상대전적 조회 동시 세션 수 (기본 4). 차단이 걱정되면 줄이세요 |
| `--limit-teams SS,KT` | 특정 구단 코드만 수집 (동작 확인용. 전체 구단 코드는 `kbo_sim/data_snapshot/teams.csv`의 `teamCode` 참고) |

## 4. 시뮬레이터가 어떤 파일을 읽는지

`kbo_sim/data_pipeline.py`는 각 CSV마다 `이름_YYYYMMDD.csv` 형태의 파일이 하나 이상
있으면 그중 **가장 최신 날짜**의 것을 읽고, 하나도 없으면 고정 파일명(`teams.csv` 등)을
읽습니다. 네 개를 한꺼번에 갈아끼울 필요는 없습니다 — 예를 들어 `batters`만 새로 받고
`matchup`은 예전 파일을 계속 쓰는 것도 됩니다.

실행하면(라이브 서버·CLI 모두) 콘솔에 실제로 어떤 파일을 읽었는지 항상 출력됩니다.

```
[초기설정] KBO 시즌 데이터 로드 중... (kbo_sim/data_snapshot)
  - teams: teams_20260908.csv
  - batters: batters_20260908.csv
  - pitchers: pitchers_20260908.csv
  - matchup: matchup_20260907.csv
[초기설정] 완료 - 팀 10개, 타자 296명, 투수 283명, 맞대결 기록 6301건
```

같은 내용이 `output/match_summary.json`, `output/repeat_summary.json`의 `data_files`
필드에도 남습니다.

## 5. 알아두어야 할 한계

- **오늘 기준 데이터입니다.** 시즌 중 실행하면 그 시점까지의 누적 기록이 들어갑니다.
  선수의 시즌 최종 성적을 보려면 시즌이 끝난 뒤 다시 받으세요.
- **방출/2군행/부상자명단인 선수는 등번호·포지션 등 기본정보를 개인기록 페이지에서
  따로 보완**합니다(오늘자 1군 등록현황에는 안 나오기 때문). 실행 로그에 몇 명을
  보완했는지 표시됩니다.
- **상대전적은 브루트포스 조회라 느립니다.** 팀 20개 조합 기준 최초 실행에 수 시간이
  걸릴 수 있습니다. 매일 새로 돌릴 필요는 없고, 필요할 때만 받으세요.
- 이 스크립트는 koreabaseball.com의 공개 페이지 구조에 맞춰 만들었습니다. 사이트
  구조가 바뀌면(페이지 이름, 컬럼 순서 등) 스크립트도 같이 고쳐야 할 수 있습니다.
